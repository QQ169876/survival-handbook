# 《穿越生存手册》

> 假如有一天你穿越回古代——这份手册就是你随身携带的"科技火种包"。
> 内容基于真实历史工艺与现代科学原理整理，多数技术为古代确实存在或现代可低成本复现的方案。

> ⚠ **先读 [`可信度说明.md`](可信度说明.md) 再用。**
> 本手册区分【史实】【科学】【经验】【存疑】四类内容：**没有标注为史实或科学的数字，一律视为经验值，必须现场验证。**
> 医疗相关（剂量、效价、疗程）本手册原则上不给数字——土法制品效价未知，给剂量等于害人。

## 为什么要做这个

许多穿越题材作品里，主角动辄"造蒸汽机、炼钢、发电"，却很少讲清楚**真实的技术门槛与实施顺序**。
本手册按"先活下来 → 再赚钱 → 后建产业"的逻辑编排，每一册都包含：材料在古代的获取方式、
可照做的步骤、失败排查表与安全红线。

  尉缭子、孙膑兵法、六韬篇幅过大或残缺较多，只给**每篇一句要点**作检索目录。

  六韬中的五音、兵征等占候篇目只作了解，不作实用推荐。
- 兵书是「说法」不是「做法」：它给原则与名分，具体编制、兵器、地形要靠自己核对
  （见册 04、13、14、18、19、21、32）。

## 使用顺序建议

0. 落地之前先读 `分册/21`（朝代选择与落地风险评估）—— 它把"选哪个朝代"换成"查清哪六件事"；
1. 先读 `分册/14`（净水与卫生）与 `分册/07`（盐糖）—— 生存刚需，且是最快变现的产业线；
2. 落地第一个冬天必须读 `分册/09`（制冰）—— 冰窖是一次错过要等一年的机会；
3. `分册/13`（止血驱虫驱兽）应在出门前读完——它是唯一不需要任何工业基础、立刻能用的手册；
4. 再读 `分册/02`（肥皂）—— 一周内可落地的生意与卫生基石；
5. `分册/01`（青霉素）—— 保命技术，永远优先；
6. `分册/17`（农业）与 `分册/20`（家常菜）决定能养多少人、能把日子过成什么样；
   `分册/29`（酿酒）应与之同步起步——它是消毒、溶剂、燃料与现金四条命脉的交汇点，
   且果酒与蜜酒不需要等粮食宽裕，落地第一年就能做；
   `分册/32`（野外求生）应与前两项同步读——它讲的是「什么都没有的第一天先做哪几件事」，
   优先级是 庇护所 > 水 > 火 > 食物；
7. `分册/04`（冶炼）与 `分册/06`（发电）是长期工程，按册内阶段推进；
8. `分册/08`（味精鸡精）与 `分册/03`（香水）属高利润精细化工，等前三步站稳再做；
9. `分册/11`（纺织）与 `分册/12`（染色）组成第一条完整产业链，是进阶篇的优先项；
   加上 `分册/25`（印花防染）后，这条链才真正闭环；
10. `分册/22`（造纸）与 `分册/23`（印刷）是知识与契约的规模化手段，产业站稳后立刻推进；
11. `分册/24`（指南针）在你要远行、勘测或布设烽燧驿路之前读；
12. `分册/18`（通信）与 `分册/19`（捕兽陷阱）按需要随时读，先立规矩、后动手；
13. `分册/28`（基础化学品）是全部化工路线的上游——当你发现某一册"默认买得到硫酸/明矾/盐酸"时，
    就该回到这一册；建议在第 7 步之后立刻着手攻硫酸；
14. `分册/27`（玻璃）与 `分册/26`（塑料）属于材料篇，排在冶炼与化工都跑通之后：
    玻璃吃燃料、塑料吃三酸，两者都是"前面全都站住了才养得起"的产业；
15. `分册/16`（医药进阶）先读它的劝退部分，再决定要不要动手；
16. `分册/15`（火药）最后再碰——本册的结论是能替代就不做；
17. `分册/10`（蒸汽机）与 `分册/05`（充电）排在最末：前者依赖前九册的全部基础且风险最高，
    后者先想清楚手机对你到底值多少工时。
18. `分册/30`、`分册/31`（兵书原文卷与白话译文卷）不挑时机，但要早：
    它们不教你做事，只教你怎么说话、怎么判断、怎么让人听你的。
    建议先读册 31 的白话，读通了再回头背册 30 的原文——能引原文，才是真的有分量。

## 发布与版本管理

本仓库同时维护 Gitee 与 GitHub 两个远端，**每次版本更新统一走一键脚本**：

    python _build/publish.py -m "提交说明"

脚本按固定顺序执行：凭据自检 → 提交 → 推送 Gitee（origin）与 GitHub（github）→ 两端各生成一个发行版，
并删除两端的旧发行版（GitHub 端连同 tag 一起清理），**始终只保留与最新提交对应的那一个发行版**。

版本号与发行说明自动取自本文件末尾「更新日志」章节的第一条，因此**更新日志必须先写、再跑脚本**。

**发行版命名与说明规则**：名称一律为「穿越生存手册 vX.Y」（项目名 + 版本号，不带其他后缀）；
说明只写**内容更新**（新增或修订了哪些分册、插图、规则），脚本、仓库维护一类条目不进发行说明——
若某版只有维护改动，说明会自动回退到最近一次内容更新并注明。

**凭据不进仓库。** 令牌与代理只放在仓库外（默认 `~/.gitee_token.json`、`~/.github_token.json`），
也可用环境变量 `GITEE_TOKEN` / `GITHUB_TOKEN` / `GITHUB_PROXY` / `GITEE_TOKEN_FILE` / `GITHUB_TOKEN_FILE` 覆盖。
推送前脚本会扫描仓库内的文本文件，一旦发现令牌、SOCKS5 代理地址或内嵌凭据的推送地址即刻中止；
所有控制台输出都会先把令牌与代理串替换成 `***`，避免终端日志泄露。

- 预演（不改动远端）：python _build/publish.py --dry
- 只提交不发布：python _build/publish.py --no-push -m "..."
- 远端：Gitee https://gitee.com/big_head_mk/survival-handbook
  GitHub https://github.com/QQ169876/survival-handbook
